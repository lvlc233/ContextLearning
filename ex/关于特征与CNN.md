## “特征”

特征是对象的一种可参与运算或可测量的表示，它能够作为后续判断、运算或学习过程的输入。

设：

- 𝒪：所有允许处理的对象构成的空间；
- O ∈ 𝒪：一个具体对象；
- 𝒞：所有允许使用的转换条件构成的空间；
- c ∈ 𝒞：一个具体转换条件；
- 𝒵：所有合法特征表示构成的空间；
- z ∈ 𝒵：一个具体特征表示。

定义特征转换机制：

> Φ : 𝒪 × 𝒞 → 𝒵

一次具体转换写作：

> z = Φ(O; c)

固定某个转换条件 c 后，它确定一个具体的特征转换算子：

> Φ_c : 𝒪 → 𝒵

定义：

> Φ_c(O) := Φ(O; c)

因此也可以写成：

> z = Φ_c(O)

对同一个对象使用不同转换条件时，可能得到不同的特征表示：

> z₁ = Φ_c₁(O)
>
> z₂ = Φ_c₂(O)

在 Φ 为确定性转换且对象 O 相同的前提下：

> z₁ ≠ z₂ ⇒ c₁ ≠ c₂

即，c₁ ≠ c₂ 是 z₁ ≠ z₂ 的必要条件，但不是充分条件。反方向一般不成立：

> c₁ ≠ c₂ ⇏ z₁ ≠ z₂



## 转换条件的获得与优化

转换条件 c 可以通过人为设计或训练得到。

设 D 是用于评价的一组对象。转换算子作用于 D，表示它被逐一应用到其中的每个对象：

> Φ_c(D) := {Φ_c(O) | O ∈ D}

令 L(c; D) 表示转换条件 c 在 D 上的损失。寻找较优转换条件可以表示为：

> c* ∈ arg min_{c ∈ 𝒞} L(c; D)

其中 c* 表示损失最小的一项或多项候选转换条件。

若 c 是可微的数值参数，可以使用梯度更新：

> c_next = c_current - η ∇_c L(c_current; D)

其中 η 是学习率。

若 c 是自然语言组成的上下文，通常不能直接进行这种梯度更新。可以采用“执行—评价—修订”的迭代过程：[具体见上下文学习]

> e_t = Eval(Φ_{c_t}(D))
>
> c_{t+1} = U(c_t, e_t)

其中 e_t 是第 t 轮的评价结果，U 是根据评价修改转换条件的更新过程。只有当评价结果实际参与后续更新时，c 才能称为可学习或可优化的转换条件；仅仅重复使用同一个 c 不构成训练。

## 对于LLM应用:


对于 LLM，转换机制 Φ 由模型 M 执行，转换条件 c 作为上下文信息参与生成。若暂时忽略随机性，可以近似写成：

> z = Φ(O; c) ≈ LLM_M(c, O)

考虑到模型的概率输出，更严格地可以写成：

> z ～ P_M(· | c, O)

这表示：给定模型 M、转换上下文 c 和对象上下文 O，具体结果 z 是模型可能输出的一个样本。

c 可作为被学习的参数

> c_next = U(c_current, evaluation)

其中 U 是更新过程，evaluation 是对当前转换结果的评价。

[详情见上]

> z = LLM_M(c, O)

[                      ]
[     转换上下文 c      ]
[                      ]       [                 ]
[         ----         ]  ───> [    特征表示 z    ]
[                      ]       [                 ]
[     对象上下文 O      ]
[                      ]

左侧方框整体表示 LLM 中的上下文，其内部包含转换上下文 c 和对象上下文 O 两部分；右侧方框表示由模型生成的特征表示 z。

转换结果也可以作为下一层转换的对象。设初始对象为 z[0] = O，则第 l 层到第 l+1 层的转换可以写成：

> z[l+1] = LLM_M(c[l], z[l])

[                      ]
[   转换上下文 c[l]     ]
[                      ]       [                     ]
[         ----         ]  ───> [  下一层表示 z[l+1]   ]
[                      ]       [                     ]
[    当前表示 z[l]      ]
[                      ]

其中，c[l] 是第 l 层使用的转换上下文。不同层可以使用不同的转换上下文；若所有层共享同一个转换上下文，则有 c[l] = c。





### 上下文空间中的内容与位置

上下文空间，是模型当前能够接收、关联和处理的全部上下文范围。这个空间中可以存在多个上下文对象；每个对象不仅具有自身的内容，还处在整个上下文中的某个位置。

因此，第 i 个上下文对象可以写成：

> O_i = (content_i, position_i)

其中：

- content_i：第 i 个对象承载的具体内容；
- position_i：该对象在整个上下文中的位置


此时特征转换可以写成：

> z_i = Φ(O_i; c) = Φ((content_i, position_i); c)

位置是否需要参与转换，取决于本次处理是否改变了对象与原上下文之间的位置关系。

一般情况下，内容被转换成特征表示 z_i，位置也可能被转换成新的位置 position'_i：

> (z_i, position'_i) = (Φ((content_i, position_i); c), PositionTransform(position_i; c))

其中，PositionTransform 表示位置的转换方式。它可以表示位置保持不变，也可以表示位置经过重排、合并或重新定位；具体方式暂不在这里展开。

当位置保持不变，并且特征结果不依赖该对象位于什么位置时，上面的表达可以缩减为只对内容进行转换：

> PositionTransform(position_i; c) = position_i，并且 Φ((content_i, position_i); c) = Φ(content_i; c)

因此，此时可以直接写成原始形式：

> z_i = Φ(content_i; c)

需要注意，位置保持不变并不自动代表位置对特征没有影响。只有当改变位置也不会改变特征结果时，才能省略 position_i。

```md
把全部带位置的局部特征记作：

> L(O) = [(Ft_1, p_1), …, (Ft_n, p_n)]

设希望得到的全局特征为 G(O)。“局部特征能够形成该全局特征”的严格条件是：

> 存在某个聚合算子 A，使 G(O) = A(L(O))

这意味着全局特征 G 可以通过局部表示 L 分解出来。

一个足够强的条件是：L 没有丢失区分原始对象所需的信息，也就是 L 在研究范围内是单射。此时可以在 L 的输出范围上定义逆操作 L⁻¹，并令：

> A = G ○ L⁻¹

于是：

> A(L(O)) = G(L⁻¹(L(O))) = G(O)

这给出了一个带条件的证明。

反过来，如果存在两个对象 O₁ 和 O₂：

> L(O₁) = L(O₂)，但 G(O₁) ≠ G(O₂)

那么任何聚合算子 A 都无法仅凭 L 的结果恢复 G。因为 A 接收到完全相同的局部表示，却被要求产生两个不同的全局结果。

因此可以得到明确回答：

> 局部 → 全局不是天然成立的性质。它成立，当且仅当局部表示保留了计算目标全局特征所需要的差异。

CNN 中的 feature map 是按位置排列的局部响应集合，因此它天然是一个“覆盖全局位置的局部响应图”；但这不等于它已经保留了任何全局语义目标所需的全部信息。深层网络通过逐层扩大感受范围计算更高层表示，但“层数增加”也不自动证明语义充分。
```

## 引用参考:
### 充分性:
充分性必须相对于一个目标来定义。若目标记作 Y，原始对象为 O，特征表示为 Ft，则一种预测意义下的充分性是：

> P(Y | O) = P(Y | Ft)

它表示：已经知道 Ft 后，再查看 O 不会增加对 Y 的判断能力。

这不意味着 Ft 中不存在与 Y 无关的信息。

反例是 Ft = O：完整复制原始对象通常保留了全部目标相关信息，也同时保留了无关信息。

所以一个结论是: “保留全部目标相关信息”对应充分性；

因此 信息瓶颈意义上的 充分压缩意味着在保证充分性的前提上，使得压缩信息尽可能的剔除目标无关的信息，


而“最小充分”表示，对于任意其他充分表示 R，都存在映射 h，使：

> Ft = h(R)

也就是说，其他充分表示还可以进一步约简为 Ft，而 Ft 自己仍然充分。
