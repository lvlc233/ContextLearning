# Agent 行为与运行环境

## 从同一份上下文的不同表现开始

假设你训练了一份 code review skill。它要求 Agent 在评审代码时不要泛泛而谈，而是先定位具体文件，再指出可以验证的风险。

第一次运行时，Agent 是这样做的：

```text
先查看登录相关文件。
调用工具：读取 src/auth/login.ts。
定位到 redirect_url 参与跳转的位置。
判断这里缺少白名单校验，存在开放重定向风险。
建议增加允许域名列表，并补充对应测试。
```

后来你把同一份 skill 换到另一个 Agent 上运行，它却只输出：

```text
整体看起来没有明显问题，建议补充测试。
```

这时你可能会想：是不是 skill 写得不够清楚？是不是应该再补一条“必须指出具体风险”的规则？

于是你开始修改 skill。你补了一条更强的规则：

```text
评审代码时，必须先读取相关文件，并指出具体风险。
```

重新运行后，结果还是没有变化。后来你才发现，第二个 Agent 根本没有仓库读取权限。它不是不想读取文件，而是不能读取文件。

于是你给它补上读取权限，再运行一次。这次它终于能打开文件了，但仍然没有指出具体风险，只是复述了几句代码结构。

后来你换了个能力更强的模型。结果它确实指出了风险，但也开始主动检查很多无关文件，输出变得很长，甚至把一些低风险问题说得很严重。

这时问题就变得复杂了：同一份 skill 的表现变化，并不只来自 skill 本身。工具权限、模型能力、运行引擎、输入信息，都会改变 Agent 最终表现出来的结果。

如果 Agent 行为完全不可观察、不可解释，训练就很难继续推进。因此，在讨论训练目标之前，需要先说明：什么是 Agent 行为，以及哪些信息会影响 Agent 行为。

## 什么是 Agent 行为

`Agent 行为` 指 Agent 在指定运行环境中运行时表现出的整体运行方式。

它不只是某段中间输出的文本，也不只是调用工具、读写文件或执行脚本这类外部动作。它还包括 Agent 在运行过程中如何理解当前输入、如何组织推理、如何规划步骤、如何生成回答，以及如何与用户交互等。

回到前面的 code review 例子，两次运行的差异并不只是“回答质量不同”。

第一次运行中，Agent 实际表现出了一组行为：

```text
读取相关文件；
定位具体代码；
形成风险判断；
给出修改建议；
补充测试方向。
```

第二次运行中，Agent 表现出的行为则明显不同：

```text
没有读取文件；
没有定位代码；
没有形成具体风险判断；
只给出了泛泛建议。
```

这类差异，就是本文所说的 `Agent 行为` 差异。

因此，观察 Agent 行为时，不应只看最终回答文本，还要看它在运行过程中如何理解当前输入、如何组织推理、怎么读取信息、怎么调用工具、怎么拆解问题、怎么执行脚本、怎么追问用户、是否遵循上下文规则，以及是否把这些过程组织成有效的运行推进方式。

而这些行为信息，正是我们训练时最直接的训练依据。

也正因为如此，上下文训练不能只评估“输出好不好”，还要评估 Agent 在运行过程中表现出的行为价值。

但仅仅知道什么是 Agent 行为还不够。真正暴露的问题是：同一份上下文为什么会在不同条件下引发不同行为？

## Agent 行为不是只由上下文决定

要理解这一点，需要先区分“写入上下文”和“行为发生”之间的差距。即上下文并不是直接控制 Agent 行为的命令。

一段上下文被传入 Agent 系统，并不意味着期望的对应行为一定会发生。它会作为 Agent 行为形成过程中的一类输入信息，影响 Agent 如何理解当前输入、如何组织推理、如何使用工具；但最终行为还会受到模型能力、运行环境、输入信息和运行机制等因素共同影响。

### 上下文如何进入模型运行

准确地说，直接影响模型当前运行的是已经进入模型输入的可见上下文。它改变的是模型在这一轮生成中的上下文条件，影响模型如何分配注意力、建立语义关联，并形成后续输出和行动倾向；因此，模型对运行边界、规则优先级和判断依据的取舍也会随之变化。

但是这种影响不是机械执行。模型不会把上下文逐条变成固定动作，而是会在当前输入、已有上下文、模型能力和运行机制中重新组织这些信息。

在这个过程中，模型会形成某种运行中的理解：当前需要处理的是什么，哪些规则优先，哪些信息可以作为依据，接下来应该倾向于输出、追问还是调用工具。

如果变化的是上下文本身，那么变化的是模型这一轮生成的条件。模型看到的边界、规则、依据和优先级不同，形成的运行理解也会不同，因此同一个模型可能表现出不同的回答方式、推理组织和行动倾向。

如果变化的是模型或运行环境，那么问题则反过来：上下文条件看起来相同，但它被理解、取用和执行的方式不同。同一段上下文可能在一个模型中形成清晰的运行结构，在另一个模型中只形成模糊倾向；也可能因为工具权限或运行机制不同，无法转化成对应行为。

因此，同一模型加载不同上下文会产生不同表现；同一份上下文换到不同模型或运行环境后，也可能出现效果衰减、变形或副作用。

### 运行引擎会改变行为如何展开

除了模型理解和执行条件，Agent 行为还受到运行引擎的影响。运行引擎决定一次运行如何推进：什么时候调用模型，给模型传入哪些上下文，如何解析模型输出，是否把输出转成工具调用，工具结果是否写回上下文，以及是否继续下一轮决策。

不同运行引擎对行为的组织方式并不相同。

在简单的chat系统中，模型输出后运行就结束了。上下文即使影响了模型理解，也主要体现在最终文本中。

在类 ReAct 机制中，模型输出会和工具结果、环境反馈一起进入下一轮调用。上下文可能影响的不只是一句话，而是多轮行动中的触发、观察和调整方式。

在 planner/executor 或 workflow 中，行为往往被拆到不同阶段或节点中。上下文可能影响计划如何形成、执行节点如何理解计划，以及节点之间如何传递中间结果。

在 MAS 中，行为还会被分配到多个 Agent 之间。上下文可能影响角色分工、运行交接、结果汇总，以及某个 Agent 的输出如何成为另一个 Agent 的输入。

运行引擎决定的是 Agent 行为如何被触发、拆分、分发、执行、观察、回写和延续。因此，同一份上下文进入不同运行机制后，可能会经过完全不同的处理：哪些内容会被选择或截断，哪些模型输出会被解析成行动，哪些中间结果会被写回或丢弃，哪些信息会被分发给其他 Agent，哪些内容又会进入下一轮模型调用。也正因为这些处理方式不同，同一份上下文才可能引发不同的行为。

### 行为发生还需要执行条件

即使运行引擎已经把某些模型输出组织成行动意图或工具调用，对应行为也不一定能够真正发生。因为 Agent 行为不是只发生在模型内部，它还需要落到具体运行环境中。

凡是涉及外部动作的上下文要求，都依赖对应的执行条件：工具是否存在，权限是否开放，资源是否可访问，环境是否允许执行，输入信息是否提供了必要材料。

如果缺少这些条件，上下文要求不会消失，但它未必能转化为真实行动。它可能停留在计划、承诺或文本表达中，也可能诱发更隐蔽的问题，例如：Agent 误以为自己已经完成了动作，编造不存在的工具、命令、文件或验证结果，或者在目标资源不存在时，把名称相近、路径相近或功能相近的对象误当成可用替代物并继续执行。

因此，训练中看到某个行为没有发生，或者看到 Agent 用错误方式“完成”了某个行为时，不能立刻判断是上下文写得不够强，或是模型能力有问题。更需要先确认：这段上下文提出的行为，在当前运行环境中是否真的具备执行条件。

### 训练观察到的是系统表现

因此，Agent 行为不是上下文单独决定的结果，而是上下文信息在某个 Agent 系统中运行后的表现。

训练中观察到的输出、工具调用、执行失败或行为改善，都不是“上下文本身”的直接样子，而是上下文与模型能力、工具权限、输入信息、运行状态和运行引擎共同作用后的结果。

这就是为什么上下文训练不能只问“这段上下文写得对不对”。更关键的问题是：这段上下文在当前 Agent 系统中，是否真的有机会被读取、理解、执行和验证。

所以，上下文训练并不是训练出一段对所有模型都完全等效的文本，而是在某个模型、运行环境和适用范围内，训练出更容易被正确读取、解释和使用的上下文信息。这也为后面的后训练留下了空间：一份上下文在某个 Agent 上已经有效，不代表换到另一个模型或运行环境后不需要再次适配。

## 这对上下文训练意味着什么

上下文训练依赖运行结果、评估和学习信号。但运行结果并不只由上下文决定。

这意味着，在分析一次训练结果时，需要区分：

```text
是上下文内容没有写清楚？
是模型能力不足以执行这条上下文？
是运行环境缺少必要工具或权限？
是输入信息没有提供足够材料？
是运行引擎没有给 Agent 使用这段上下文的机会？
```

如果不区分这些因素，训练过程就容易把环境问题误判为上下文问题，或者把模型偶然表现误判为上下文修改有效。

因此，Agent 行为与运行环境是观察训练结果时必须先确认的背景条件。只有先明确训练结果发生在哪里，后续才更容易讨论训练目标、学习信号和优化方向。
