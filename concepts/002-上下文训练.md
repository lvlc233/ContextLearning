# 上下文训练

## 从一个简单训练开始

假如你在练习投篮，真正让你学会投篮的不是一个关于如何学会投篮的视频。当然看视频也不是完全没有价值，你可以通过他快速的了解一些概念，但是并不代表你在真实的球场上可以投出好球

这是你第一天进入球场开始投篮，你拿起陌生的球，不习惯的打着，你找到一个合适的位置，两只手抱着球，身体前倾，双脚蓄力，将球向上抛起，pan，球飞了，没有进框

后来你看了一个视频，了解了怎么投篮，你照着视频中的样子投递，这次你做了一个很完美的动作，但是球偏了，这次尝试让你感觉不错，你感受的当时投球时的感觉，动作，发力方式调整你的xxx，你再次投球，这次方向对了但是力气小了，你不断的调整，终于你投10球基本有7球进了，这让你学会了一些投球真正的适合你自己的技巧，例如发力方式，投掷角度。。。
这次，你想尝试不同的方向投球，结果虽然只是位置不同了，但是你的投球手感变了...在多次联系，观察别人的投球方式，你渐渐的掌握的了适合你的投球技巧，这使得在你的能力范围只内，你都可以准确的投球，尽管有时候还是会投空，但是你现在已经不是当初照猫画虎的样子，而是真正掌握了属于你自己的技巧。

真正的训练发生在一次次投篮之后：球偏左、偏短、弧线太平、出手太慢，这些结果都会成为判断动作哪里偏离目标的依据。

如果只看一次投篮，很难判断问题是否稳定存在。一次偏左可能只是偶然；但如果连续几次都偏左，就不再只是一个结果，而是一个信号：当前出手动作里可能存在稳定偏差。

于是下一轮练习就不只是“继续投”，而是带着调整方向继续投：手腕回正一点、发力更充分一点、出手点再高一点。

接下来，练习者继续投篮，再观察结果，再调整动作。训练不是期待一次调整就完成，而是通过多次表现、评估和反馈，让动作逐渐稳定地接近目标。

`上下文训练` 也是类似的。只是训练对象从“动作”换成了 `上下文信息`：我们观察 Agent 加载上下文后的行为，评估它和目标行为之间的偏差，再把这些偏差转成调整上下文的依据。

## 什么是上下文训练

`上下文训练` 指的是：围绕训练目标，通过样本运行、结果评估和学习信号，对 `上下文信息` 进行多轮调整，使 Agent 在加载这份上下文后，更稳定地产生接近期望的行为。

这里的训练不是模型参数训练。

在模型参数训练中，被更新的是模型内部参数。训练完成后，模型本身发生变化。

在上下文训练中，被调整的是模型外部可加载的上下文信息。模型参数不变，但 Agent 在运行时读取到的上下文发生变化，因此它理解任务、选择动作、组织输出或调用工具的方式也可能发生变化。

## 训练目标不一定一开始就清楚

投篮训练里，“投进篮筐”是一个很明确的目标。但在上下文训练中，训练目标不一定在训练开始时就已经完整明确。

很多时候，它先隐含在人类偏好、样本表现、失败现象或版本对比中。训练的一部分工作，就是在观察和评估过程中，逐步把这些隐含目标提炼出来。

例如，人类最初可能只是觉得：

```text
这个 Agent 的回复不太会教。
这个 skill 用起来有点飘。
这一版比上一版稳定，但太容易泛泛而谈。
```

这些判断还不是清晰的训练目标，但它们可能包含后续目标的来源。

## 基本元素

一次上下文训练至少需要区分几个元素：

- **上下文本体**：被训练或被修改的上下文，例如 skill、prompt、rule。
- **训练目标**：希望上下文影响 Agent 后产生的行为方向。
- **训练样本**：用于暴露问题、运行任务、形成信号或验证泛化的材料。
- **评估方式**：判断一次输出、一次修改或一个版本是否更接近目标的方式。
- **学习信号**：运行、标注、测试或版本对比中产生的判断依据。
- **优化方向**：根据学习信号整理出的上下文调整方向。
- **测试与 checkpoint**：用于比较版本、观察稳定性和防止漂移。

这些元素不一定一开始就全部完备。早期训练可能只有一个粗糙目标、一组失败样本和几条人工反馈。随着训练推进，这些元素才会逐步变得清晰。

## 训练对象

上下文训练的对象不是某一种具体文件格式，也不是单独的 prompt、skill 或 memory。

这些都只是 `上下文信息` 的不同形态：

- system prompt；
- skill；
- memory；
- 工具说明；
- 项目规则；
- 示例、反例或运行记录；
- 其他会被 Agent 加载并影响行为的内容。

训练真正调整的是这些上下文内容本身，以及它们在上下文空间中的组织方式。

例如，一次训练可能会：

- 增加一条判断规则；
- 删除一段冗余说明；
- 重写一个容易误导 Agent 的案例；
- 拆分一组互相干扰的规则；
- 合并重复表达；
- 调整某段上下文的适用条件。

## 最小训练过程

一个最小的上下文训练过程通常包括：

```text
明确训练目标
→ 加载当前上下文
→ 输入样本或运行任务
→ 观察 Agent 输出或行为
→ 评估结果
→ 获得学习信号
→ 形成优化方向
→ 调整上下文信息
→ 再次测试
```

这个过程不要求一开始就自动化。早期训练完全可以由人类手动完成：观察一次输出，判断哪里偏离目标，修改上下文，再用样本重新测试。

关键不在于训练由人还是系统执行，而在于每次调整是否有依据、是否能被记录、是否能在后续样本中被重新验证。

## 训练为什么需要多轮

一次上下文修改通常只能说明：在当前样本、当前模型和当前运行环境中，某种调整看起来产生了影响。

但这还不足以说明上下文真的被训练好了。

上下文训练需要多轮，是因为 Agent 行为会受到多个因素影响：

- 样本不同，暴露的问题不同；
- 模型不同，对同一上下文的理解不同；
- 运行环境不同，可用工具和执行方式不同；
- 上下文内容之间可能互相增强，也可能互相干扰；
- 某次修改可能改善一个目标，同时破坏另一个目标。

因此，上下文训练不是“改一次就结束”，而是通过多次运行、评估、调整和测试，让上下文影响行为的方式逐步变得更稳定。

## 与上下文优化的区别

普通上下文优化可以很轻量：看到一次输出不好，就补一条规则；发现一段话冗余，就删掉它。

这类修改可以有价值，但它不一定构成训练。

当修改开始围绕明确目标进行，并且修改前后有样本、评估、学习信号和版本对比时，它才更接近 `上下文训练`。

换句话说：

```text
上下文优化关注的是：这段上下文能不能改得更好。
上下文训练关注的是：这段上下文是否正在通过可观察的反馈，稳定逼近某个目标行为。
```
