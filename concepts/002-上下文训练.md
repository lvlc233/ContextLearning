# 上下文训练

## 从一个简单训练开始

假如你第一次去球场投篮。

你站在篮筐下面，手里抱着一个有点陌生的球。你知道球要往篮筐里去，于是身体往前一倾，脚下用力，手一抬，球飞了出去。

```text
砰。
```

球砸到篮板边上，弹走了。

你捡回来，再投一次。这次方向好像对了一点，但球短了，连篮筐都没碰到。你又投，球飞高了；再投，球偏到右边。刚开始的时候，你甚至说不清自己到底哪里不对，只能一边投，一边记住刚才那一下是什么感觉。

投了几次之后，你开始发现一些东西。手腕歪一点，球就容易偏；力气小一点，球就短；出手太急，球的弧线就很平。于是你下一次投的时候，会下意识地改一点：手腕收回来一点，力气加一点，出手慢一点。

有时候改完之后还是不进，但你能感觉到球离篮筐近了一点。再投，再看，再改。慢慢地，你不再只是把球往篮筐那里扔，而是在根据每一次结果调整自己的动作。

后来你在一个位置上能进得比较稳定了，就换一个角度试试。结果手感又变了，之前好用的发力方式不完全适用。于是你又重新试，重新调整。直到最后，你学会的不是某一个固定动作，而是在不同位置、不同距离下，知道怎么根据球的结果把动作调回来。

## 什么是上下文训练

`上下文训练` 是 `上下文学习` 中的具体实践过程，它指的是通过某种具体的训练方式，获得或调整一段 `上下文信息`，使 Agent 系统在目标环境中使用这段上下文信息时，可以更稳定地达到训练目标的过程。


如果把上述案例抽象成一个训练过程，那么在学习投篮这件事中，目标很简单：学会一种更稳定有效的投球方式。

这里说的是 `学习投篮`，而不是 `训练投篮`。学习指最终形成某种能力，训练则是为了形成这种能力而反复尝试、观察、调整和再尝试的过程。

接下来，训练过程会不断重复：

```text
1. 执行动作：一次次出手投篮。
2. 观察结果：球偏了、短了、高了，或者更接近篮筐。
3. 分析原因：从每次投篮结果中判断哪里不对。
4. 调整经验：改变手腕、力度、出手节奏。
5. 再次尝试：带着调整后的动作继续投篮。
```

当你在不同站位、角度或距离下都能比较稳定地投球时，才说明这套投球技巧已经不只是适配某一次出手，而是形成了相对稳定的能力。

映射到 `上下文训练` 中，训练目标通常是：希望训练后达到某种预期效果。

接下来，训练过程会不断重复：

```text
1. 运行任务：让 Agent 加载当前上下文并执行样本或任务。
2. 观察结果：查看 Agent 输出、工具调用、交互方式或任务完成情况。
3. 分析偏差：判断当前行为和训练目标之间的差距。
4. 调整上下文：修改、增加、删除或重组上下文信息。
5. 再次测试：用样本或任务重新运行，观察行为是否更接近目标。
```

当这段上下文信息在不同样本、任务或运行条件下，都能更稳定地达到训练目标时，才说明它不只是适配了某一次输出，而是形成了更稳定的上下文效果。

如果了解机器学习，也可以把它粗略类比为：

```text
输入数据 → 前向传播 → 计算 loss / reward → 反向传播得到梯度 → 更新模型参数
```

对应到上下文训练中，就是：

```text
输入样本 → 运行 Agent → 评估输出 → 获得学习信号 → 形成优化方向 → 调整上下文信息
```

## 基本元素

在上下文训练至少需要包含以下几个要素：

| 要素 | 含义 | 案例 |
| --- | --- | --- |
| 受训练对象 | 通常是一段 `上下文信息`。 | 一份 code review skill、一段 system prompt、一组项目规则.... |
| 训练目标 | 希望训练后达到的预期效果或目标状态。 | 诱发某种 Agent 行为、保持既有功能不变、减少上下文长度、适配新环境.... |
| 运行环境 | Agent 加载上下文并执行任务的环境。 | 使用模型、工具权限、harness、运行沙箱.... |
| 训练材料 | 用于运行、评估、比较或验证的样本、任务、标注、运行记录或数据集。 | 一次 run 记录、失败输出、人工偏好标注、一组测试样本... |
| 评估依据 | 用于对当前信息进行价值判断的标准、规则、偏好、指标或参照。 | 是否能按照某种递进关系准确找到目标文件、是否可以对话不啰嗦 |
| 学习信号 | 在评估过程中成为对某一目标或中间阶段有学习价值的信息。 | “正确:找到目标文件，错误:但没有指出具体风险” |
| 优化方向 | 根据学习信号整理出的下一步调整方向。 | 正面效果可能来自“先定位目标文件”的步骤，负面效果可能来自“缺少风险判断标准”的上下文缺口；下一轮应保留定位能力，并补强风险判断。 |
| 优化器 | 执行训练对象内容信息调整的方式。 | 根据优化方向直接优化、小步采样优化 |

这些元素并不一定需要在训练前就准备好，这正是`上下文训练`有别于`参数训练`的部分：即`行为信息本身可以作为信号参数`。早期训练可能只有一个粗糙目标、一组失败样本和几条人工反馈。随着训练推进，这些元素能够逐步变得清晰。

其中，`受训练对象` 需要特别说明：上下文训练调整的不是某一种具体的文件，或某一次输出结果。

system prompt、skill、memory、tool schema、项目规则、示例或运行记录，都只是 `上下文信息` 的不同形态。训练真正调整的是这些上下文内容本身，以及它们在 `上下文空间` 中的组织方式。

至于上下文空间如何选择、删除、扩展、采样、组合和重写，会在后续章节继续展开。

## 最小训练过程

一次最小的上下文训练，至少需要先确定几个基础条件：

```text
训练目标：希望训练后达到什么预期效果。
受训练对象：从哪一段上下文信息开始训练。
运行环境：在哪个 Agent 环境中运行与观察。
训练材料：使用哪些样本、任务、标注、运行记录或数据集参与训练。
评估依据：用于对当前信息进行价值判断的标准、规则、偏好、指标或参照。
```

随后，训练循环会不断重复：

```text
运行任务
→ 评估结果
→ 获得学习信号
→ 形成优化方向
→ 通过优化器调整上下文信息
→ 再次测试
```

这个过程不要求一开始就自动化。早期训练完全可以由人类手动完成：观察一次输出，判断哪里偏离目标，修改上下文，再用样本重新测试。

关键不在于训练由人还是系统执行，而在于每次调整是否有依据、是否能被记录、是否能在后续样本中被重新验证。

## 常见训练方式

从学习信号来源看，上下文训练可以粗略分为几种形式：

- **监督式上下文训练**：有明确标注、参考答案、规则标准或人工判断，用它们指导上下文调整。
- **偏好式上下文训练**：没有唯一标准答案，但可以比较哪个输出、版本或上下文更接近训练目标。
- **强化式上下文训练**：通过环境反馈、任务成功或失败、奖励或评分来推动上下文调整。
- **自监督式上下文训练**：利用上下文自身、运行记录或结构约束构造学习信号，不完全依赖人工标注。
- **后训练适配**：在已有上下文训练结果基础上，继续适配新模型、新环境、新任务或新偏好。

## 训练中的注意事项

上下文训练不是改一次上下文、看一次输出就结束。由于模型输出本身带有概率性，单次运行结果可能受到采样、上下文状态、模型版本、工具权限和运行环境等各种影响，因此一次看起来有效的修改，不一定说明上下文已经稳定达到训练目标。

训练时还需要注意模型幻觉、上下文长度、运行成本和副作用等问题。上下文越长，运行成本、延迟和注意力干扰可能越高；多轮训练也可能带来重复运行、重复加载上下文和 KV cache 相关成本。某次修改可能改善一个样本，却破坏其他任务或已有能力。

因此，上下文训练通常需要多轮运行、评估和调整。多轮训练的目的不是不断堆叠规则，而是观察上下文修改是否能在不同样本、任务或运行条件下稳定产生预期效果并具有泛化性。
