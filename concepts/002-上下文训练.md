# 上下文训练

## 从一个简单训练开始

假如你第一次去球场投篮。

你站在篮筐下面，手里抱着一个有点陌生的球。你知道球要往篮筐里去，于是身体往前一倾，脚下用力，手一抬，球飞了出去。

```text
砰。
```

球砸到篮板边上，弹走了。

你捡回来，再投一次。这次方向好像对了一点，但球短了，连篮筐都没碰到。你又投，球飞高了；再投，球偏到右边。刚开始的时候，你甚至说不清自己到底哪里不对，只能一边投，一边记住刚才那一下是什么感觉。

投了几次之后，你开始发现一些东西。手腕歪一点，球就容易偏；力气小一点，球就短；出手太急，球的弧线就很平。于是你下一次投的时候，会下意识地改一点：手腕收回来一点，力气加一点，出手慢一点。

有时候改完之后还是不进，但你能感觉到球离篮筐近了一点。再投，再看，再改。慢慢地，你不再只是把球往篮筐那里扔，而是在根据每一次结果调整自己的动作。

后来你在一个位置上能进得比较稳定了，就换一个角度试试。结果手感又变了，之前好用的发力方式不完全适用。于是你又重新试，重新调整。直到最后，你学会的不是某一个固定动作，而是在不同位置、不同距离下，知道怎么根据球的结果把动作调回来。

## 什么是上下文训练

`上下文训练` 指的是：围绕训练目标，通过样本运行、结果评估和学习信号，对 `上下文信息` 进行多轮调整，使 Agent 在加载这份上下文后，更稳定地产生接近期望的行为。


| 训练 | `训练` 指为了让上下文加载后更稳定地产生目标行为，通过评估输出、获取学习信号并调整上下文信息的过程。 | 根据一次代码评审输出的偏离信号，调整 skill 中的评审规则。 | null |

这里的训练不是模型参数训练。

在模型参数训练中，被更新的是模型内部参数。训练完成后，模型本身发生变化。

在上下文训练中，被调整的是模型外部可加载的上下文信息。模型参数不变，但 Agent 在运行时读取到的上下文发生变化，因此它理解任务、选择动作、组织输出或调用工具的方式也可能发生变化。

## 训练目标不一定一开始就清楚

投篮训练里，“投进篮筐”是一个很明确的目标。但在上下文训练中，训练目标不一定在训练开始时就已经完整明确。

很多时候，它先隐含在人类偏好、样本表现、失败现象或版本对比中。训练的一部分工作，就是在观察和评估过程中，逐步把这些隐含目标提炼出来。

例如，人类最初可能只是觉得：

```text
这个 Agent 的回复不太会教。
这个 skill 用起来有点飘。
这一版比上一版稳定，但太容易泛泛而谈。
```

这些判断还不是清晰的训练目标，但它们可能包含后续目标的来源。

## 基本元素

一次上下文训练至少需要区分几个元素：

- **上下文本体**：被训练或被修改的上下文，例如 skill、prompt、rule。
- **训练目标**：希望上下文影响 Agent 后产生的行为方向。
- **训练样本**：用于暴露问题、运行任务、形成信号或验证泛化的材料。
- **评估方式**：判断一次输出、一次修改或一个版本是否更接近目标的方式。
- **学习信号**：运行、标注、测试或版本对比中产生的判断依据。
- **优化方向**：根据学习信号整理出的上下文调整方向。
- **测试与 checkpoint**：用于比较版本、观察稳定性和防止漂移。

这些元素不一定一开始就全部完备。早期训练可能只有一个粗糙目标、一组失败样本和几条人工反馈。随着训练推进，这些元素才会逐步变得清晰。

## 训练对象

上下文训练的对象不是某一种具体文件格式，也不是单独的 prompt、skill 或 memory。

这些都只是 `上下文信息` 的不同形态：

- system prompt；
- skill；
- memory；
- 工具说明；
- 项目规则；
- 示例、反例或运行记录；
- 其他会被 Agent 加载并影响行为的内容。

训练真正调整的是这些上下文内容本身，以及它们在上下文空间中的组织方式。

例如，一次训练可能会：

- 增加一条判断规则；
- 删除一段冗余说明；
- 重写一个容易误导 Agent 的案例；
- 拆分一组互相干扰的规则；
- 合并重复表达；
- 调整某段上下文的适用条件。

## 最小训练过程

一个最小的上下文训练过程通常包括：

```text
明确训练目标
→ 加载当前上下文
→ 输入样本或运行任务
→ 观察 Agent 输出或行为
→ 评估结果
→ 获得学习信号
→ 形成优化方向
→ 调整上下文信息
→ 再次测试
```

这个过程不要求一开始就自动化。早期训练完全可以由人类手动完成：观察一次输出，判断哪里偏离目标，修改上下文，再用样本重新测试。

关键不在于训练由人还是系统执行，而在于每次调整是否有依据、是否能被记录、是否能在后续样本中被重新验证。

## 训练为什么需要多轮

一次上下文修改通常只能说明：在当前样本、当前模型和当前运行环境中，某种调整看起来产生了影响。

但这还不足以说明上下文真的被训练好了。

上下文训练需要多轮，是因为 Agent 行为会受到多个因素影响：

- 样本不同，暴露的问题不同；
- 模型不同，对同一上下文的理解不同；
- 运行环境不同，可用工具和执行方式不同；
- 上下文内容之间可能互相增强，也可能互相干扰；
- 某次修改可能改善一个目标，同时破坏另一个目标。

因此，上下文训练不是“改一次就结束”，而是通过多次运行、评估、调整和测试，让上下文影响行为的方式逐步变得更稳定。

## 与上下文优化的区别

普通上下文优化可以很轻量：看到一次输出不好，就补一条规则；发现一段话冗余，就删掉它。

这类修改可以有价值，但它不一定构成训练。

当修改开始围绕明确目标进行，并且修改前后有样本、评估、学习信号和版本对比时，它才更接近 `上下文训练`。

换句话说：

```text
上下文优化关注的是：这段上下文能不能改得更好。
上下文训练关注的是：这段上下文是否正在通过可观察的反馈，稳定逼近某个目标行为。
```
