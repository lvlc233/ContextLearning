# 上下文训练

## 从一个简单训练开始

假如你第一次去球场投篮。

你站在篮筐下面，手里抱着一个有点陌生的球。你知道球要往篮筐里去，于是身体往前一倾，脚下用力，手一抬，球飞了出去。

```text
砰。
```

球砸到篮板边上，弹走了。

你捡回来，再投一次。这次方向好像对了一点，但球短了，连篮筐都没碰到。你又投，球飞高了；再投，球偏到右边。刚开始的时候，你甚至说不清自己到底哪里不对，只能一边投，一边记住刚才那一下是什么感觉。

投了几次之后，你开始发现一些东西。手腕歪一点，球就容易偏；力气小一点，球就短；出手太急，球的弧线就很平。于是你下一次投的时候，会下意识地改一点：手腕收回来一点，力气加一点，出手慢一点。

有时候改完之后还是不进，但你能感觉到球离篮筐近了一点。再投，再看，再改。慢慢地，你不再只是把球往篮筐那里扔，而是在根据每一次结果调整自己的动作。

后来你在一个位置上能进得比较稳定了，就换一个角度试试。结果手感又变了，之前好用的发力方式不完全适用。于是你又重新试，重新调整。直到最后，你学会的不是某一个固定动作，而是在不同位置、不同距离下，知道怎么根据球的结果把动作调回来。

## 什么是上下文训练

`上下文训练` 是 `上下文学习` 中的具体实践过程，它指的是通过某种具体的训练方式，获得或调整一段 `上下文信息`，使 Agent 系统在目标环境中使用这段上下文信息时，可以稳定地产生目标行为的过程。


如果把上述案例抽象成一个训练过程，那么在学习投篮这件事中，目标很简单：学会一种更稳定有效的投球方式。

这里说的是 `学习投篮`，而不是 `训练投篮`。学习指最终形成某种能力，训练则是为了形成这种能力而反复尝试、观察、调整和再尝试的过程。

接下来，训练过程会不断重复：

```text
1. 执行动作：一次次出手投篮。
2. 观察结果：球偏了、短了、高了，或者更接近篮筐。
3. 分析原因：从每次投篮结果中判断哪里不对。
4. 调整经验：改变手腕、力度、出手节奏。
5. 再次尝试：带着调整后的动作继续投篮。
```

当你在不同站位、角度或距离下都能比较稳定地投球时，才说明这套投球技巧已经不只是适配某一次出手，而是形成了相对稳定的能力。

映射到 `上下文训练` 中，训练目标通常是：期望 Agent 稳定产生某种行为。

接下来，训练过程会不断重复：

```text
1. 运行任务：让 Agent 加载当前上下文并执行样本或任务。
2. 观察结果：查看 Agent 输出、工具调用、交互方式或任务完成情况。
3. 分析偏差：判断当前行为和训练目标之间的差距。
4. 调整上下文：修改、增加、删除或重组上下文信息。
5. 再次测试：用样本或任务重新运行，观察行为是否更接近目标。
```

当这段上下文信息在不同样本、任务或运行条件下，都能更稳定地诱发目标行为时，才说明它不只是适配了某一次输出，而是形成了更稳定的上下文效果。

如果了解机器学习，也可以把它粗略类比为：

```text
输入数据 → 前向传播 → 计算 loss / reward → 反向传播得到梯度 → 更新模型参数
```

对应到上下文训练中，就是：

```text
输入样本 → 运行 Agent → 评估输出 → 获得学习信号 → 形成优化方向 → 调整上下文信息
```

## 基本元素

在上下文训练至少需要包含以下几个要素：

| 要素 | 含义 | 案例 |
| --- | --- | --- |
| 受训练对象 | 通常是一段 `上下文信息`。 | 一份 code review skill、一段 system prompt、一组项目规则.... |
| 训练目标 | 希望上下文加载到 Agent 后稳定诱发的目标行为。 | 提交Agent的代码审核质量.... |
| 运行环境 | Agent 加载上下文并执行任务的环境。 | 使用模型、工具权限、harness、运行沙箱.... |
| 训练材料 | 用于运行、观察或分析的样本、数据标注或运行记录。 | 一次run记录、失败输出、人工偏好标注... |
| 评估依据 | 根据某种标准判断运行时信息是否具备某种价值的依据。 | 是否能按照某种递进关系准确找到目标文件、是否可以对话不啰嗦 |
| 学习信号 | 在评估过程中成为对某一目标或中间阶段有学习价值的信息。 | “正确:找到目标文件，错误:但没有指出具体风险” |
| 优化方向 | 根据学习信号整理出的下一步调整方向。 | 正面效果可能来自“先定位目标文件”的步骤，负面效果可能来自“缺少风险判断标准”的上下文缺口；下一轮应保留定位能力，并补强风险判断。 |
| 优化器 | 执行训练对象内容信息调整的方式。 | 根据优化方向直接优化、小步采样优化 |

这些元素并不一定需要在训练前就准备好，这正是`上下文训练`有别与`参数训练`的部分--即`参数本身就是行为信息本身`。早期训练可能只有一个粗糙目标、一组失败样本和几条人工反馈。随着训练推进，这些元素能够逐步变得清晰。


## 训练调整的是什么

上下文训练的对象不是某一种具体文件格式，也不是单独的 prompt、skill 或 memory。

这些都只是 `上下文信息` 的不同形态：

- system prompt；
- skill；
- memory；
- 工具说明；
- 项目规则；
- 示例、反例或运行记录；
- 其他会被 Agent 加载并影响行为的内容。

训练真正调整的是这些上下文内容本身，以及它们在`上下文空间`中的组织方式。

例如，一次训练可能会：

- 增加一条判断规则；
- 删除一段冗余说明；
- 重写一个容易误导 Agent 的案例；
- 拆分一组互相干扰的规则；
- 合并重复表达；
- 调整某段上下文的适用条件。

## 最小训练过程

一个最小的上下文训练过程通常包括：

```text
确定训练目标
→ 准备训练材料
→ 选择当前上下文
→ 运行样本或任务
→ 观察 Agent 输出或行为
→ 评估结果
→ 获得学习信号
→ 形成优化方向
→ 调整上下文信息
→ 保存 checkpoint
→ 再次测试
```

这个过程不要求一开始就自动化。早期训练完全可以由人类手动完成：观察一次输出，判断哪里偏离目标，修改上下文，再用样本重新测试。

关键不在于训练由人还是系统执行，而在于每次调整是否有依据、是否能被记录、是否能在后续样本中被重新验证。

## 常见训练方式

上下文训练可以通过不同方式展开。

常见训练方式包括：

- **人工训练**：由人观察输出、判断问题，并手动调整上下文。
- **样本训练**：用一组样本反复运行，根据表现调整上下文。
- **标注训练**：通过人工标注、偏好选择或对错判断产生学习信号。
- **评估训练**：用规则、评分器或测试标准对结果进行评估，再根据评估结果调整。
- **对比训练**：比较两个版本、两个输出或两段上下文，选择更接近目标的一方。
- **自动训练**：由系统自动运行、评估、修改和再次测试。
- **后训练**：在已有训练结果基础上继续适配新模型、新环境或新目标。

## 训练为什么需要多轮

一次上下文迭代通常只能说明：在当前样本、当前模型和当前运行环境中，某种调整看起来产生了影响。

但这还不足以说明上下文真的被训练好了。

上下文训练需要多轮，是因为 Agent 行为会受到多个因素影响：

- 样本不同，暴露的问题不同；
- 模型不同，对同一上下文的理解不同；
- 运行环境不同，可用工具和执行方式不同；
- 上下文内容之间可能互相增强，也可能互相干扰；
- 某次修改可能改善一个目标，同时破坏另一个目标。

因此，上下文训练不是“改一次就结束”，而是通过多次运行、评估、调整和测试，让上下文影响行为的方式逐步变得更稳定。

## 与上下文优化的区别

普通上下文优化可以很轻量：看到一次输出不好，就补一条规则；发现一段话冗余，就删掉它。

这类修改可以有价值，但它不一定构成训练。

当修改开始围绕明确目标进行，并且修改前后有样本、评估、学习信号和版本对比时，它才更接近 `上下文训练`。

换句话说：

```text
上下文优化关注的是：这段上下文能不能改得更好。
上下文训练关注的是：这段上下文是否正在通过可观察的反馈，稳定逼近某个目标行为。
```
