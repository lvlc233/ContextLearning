# 评估与学习信号

## 从一次运行结果开始

你是一名软件开发者。今天，你刚完成一个登录跳转功能，希望在提交代码前先检查其中是否存在遗漏。

你从网络上找到一份用于代码评审的 skill，把它加载到 Agent 中，并让 Agent 评审这次修改。

运行结束后，Agent 给了你一份报告，上面显示：

```text
评审结论：建议修改后合并。

1. src/auth/redirect.ts:42
   redirectUrl 来自请求参数，建议限制允许跳转的域名，
   否则可能产生开放重定向风险。

2. src/auth/session.ts:18
   用户 ID 被写入 session，可能泄露用户隐私，建议删除。

3. 测试建议
   建议补充正常登录和登录失败场景的测试。
```

这份报告看起来相当完整。它给出了明确结论，定位了具体文件和代码位置，解释了风险，还补充了测试建议。至少与“整体没有明显问题”一类泛泛评价相比，它已经更像一份可以用于修改代码的评审报告。

但这份评审真的有效吗？

你开始逐项检查报告。第一项判断是正确的：跳转地址确实缺少域名限制，报告也准确指出了风险发生的位置。第二项却有问题：用户 ID 本来就需要被写入服务端 session，它不会因此暴露给其他用户，这项意见虽然定位到了代码，却没有形成正确的风险判断。

测试建议同样不完全令人满意。“正常登录”和“登录失败”确实需要测试，但它们没有验证报告刚刚指出的开放重定向风险。继续查看运行记录后，你还发现 Agent 读取了两个相关文件，却没有查看负责校验回调地址的配置文件；而真正决定漏洞是否成立的白名单配置，就在那里。

现在，同一次运行中同时出现了几种表现：Agent 成功定位并解释了一个风险，提出了一项没有依据的风险判断，给出了相关但不足以验证风险的测试建议，并且遗漏了影响结论成立的配置文件。

事实上，从你开始追问“这份评审是否有效”，并根据实际代码逐项判断报告中的结论时，`评估`就已经发生了。

查看代码、配置和运行记录，让你获得了用于判断的更多信息；确认风险是否成立、意见是否属于误报、测试建议是否有用，则是在这些信息的基础上，逐步形成对这份报告及其具体表现的价值判断。

## 什么是评估

`评估`是从某种判断依据出发，对事物形成价值判断的过程。

评估并不限定于某一种对象。信息、行为、结果、方案、状态、过程，以及它们之间的变化，都可以成为被评估的事物。评估时使用的信息也不一定就是评估对象本身：一份记录可以直接接受评估，也可以作为判断某项行为或结果的相关信息。

判断依据为评估提供了认识价值的尺度。它可以来自目标、规则、需求、偏好、经验、指标或参照，也可能没有被明确写出。但无论是否被明确表达，价值判断总是相对于某种依据形成的。

因此，价值不是事物自身固定携带的属性。同一个事物，在不同判断依据下可能具有不同价值；同一种表现，也可能同时具有正面价值、负面价值或尚待确认的价值。评估所做的不是再次描述事物是什么，而是形成关于它是否可取、是否重要、是否值得保留、接受、抑制或继续关注的判断。

观察、测量、验证和分析都可能参与评估，但它们并不天然等于评估。观察说明发生了什么，测量获得某种状态或数值，验证确认某项陈述是否成立，分析则可以帮助理解结构、关系或原因。只有当这些内容被进一步用于认识某个事物的价值时，才进入评估。

评估形成价值判断，但不直接负责解释问题为什么发生，也不直接决定接下来应该怎样修改或行动。这些判断可以继续支持归因、决策或优化，但它们属于评估之后可能发生的活动。

## 上下文训练中的评估

在上下文训练中，评估的含义没有发生变化。变化的是接受评估的对象、采用的判断依据，以及评估所产生的判断信息所可能参与的后续过程。

一次 Agent 运行、某项具体行为、一份最终输出或一次上下文版本比较，都可以成为评估对象。训练目标、评估规则、人类偏好或测试标准，则可以成为价值判断的依据。借助这些依据，我们可以进一步判断这些对象对于当前训练具有什么价值。

回到前面的代码评审的案例。此前逐项核对风险是否成立、测试建议是否有效，是在评估这份报告本身。当我们试图想要对这个skill进行调整的是评估便会继续追问：这些表现相对于当前训练目标意味着什么？
---
根据这些依据评估本次运行，可以形成这样的判断：

```text
Agent 准确定位并解释了开放重定向风险，表现出了目标所要求的风险定位能力；
Agent 将正常的 session 行为判断为隐私风险，说明当前风险判断仍然存在误报；
Agent 给出的测试建议没有覆盖开放重定向场景，尚未形成可验证的风险判断。
```

在这个过程中，训练目标规定了希望达到的效果，评估依据提供了判断当前表现的尺度，而评估则面对本次实际运行形成了具体的价值判断。

## 信息如何成为学习信号

上面的评估已经形成了对本次运行的价值判断，但这些判断并不因此自动成为学习信号。只有当某项判断能够进一步反映当前训练中已经出现的效果、仍然存在的偏离或值得继续关注的变化时，它才开始具有学习价值。

这个关系可以概括为：

```text
事物及相关信息
→ 评估形成价值判断
→ 判断对当前训练具有学习价值
→ 成为学习信号
```

例如，“Agent 将正常的 session 行为判断为隐私风险”可以只是对当前报告中一项误报的判断；当它进一步用于反映当前训练在风险判断准确性上仍然存在偏离时，这项判断才成为当前训练中的学习信号。

## 评估如何发生

评估不只由一种方式完成。人类可以直接判断一次输出，也可以比较两个上下文版本的表现；规则可以检查输出是否包含必要结构，测试程序可以验证任务是否成功，运行环境也可以通过成功、失败、奖励或状态变化提供反馈。

常见的评估方式包括：

- 人类评价与偏好比较；
- 规则或评估函数判断；
- 测试、断言和任务完成结果；
- 环境反馈与运行状态；
- 不同输出、上下文版本或 checkpoint 之间的比较；
- 数据标注。

`数据标注`是记录评估判断的一种常见方式。标注可以只记录“好 / 坏”“更好 / 更差”，也可以进一步记录判断位置、理由和偏差。

例如：

```text
压缩有效，但不能接受，因为它删除了失败条件和测试标准。
```

这条标注不只是一个接受或拒绝的结论。它还记录了判断所依据的具体变化：上下文长度减少了，但训练希望保留的关键约束同时丢失了。

标注本身不等同于上下文规则，也不需要被逐字写入上下文。它首先保存的是一次评估判断，后续可以继续参与信号整理、版本比较或上下文调整。

## 什么是学习信号

`学习信号`指在上下文训练过程中体现出来的、对当前训练具有学习价值的反馈、监督或评价信息。

在早期文档或流程语境中，它也可能被称为`训练信号`、`训练反馈信号`或`反馈信号`。本文后续统一使用`学习信号`。

学习信号可以来自人类反馈、样本表现、失败案例、数据标注、版本比较、测试结果或环境反馈。它所表达的不是“发生了什么”这一事实本身，而是这项信息在当前训练中具有怎样的判断意义。

训练目标、学习信号和优化方向之间不是同一个概念：

```text
训练目标：训练希望逼近、保持、强化或避免什么效果。
学习信号：当前训练中体现出了什么具有学习价值的判断。
优化方向：根据当前训练状态，下一步应当朝什么方向调整。
```

学习信号不会直接修改上下文。它还需要结合训练过程中的其他信息，被整理为评估结论、优化方向或上下文修改依据。

## 学习信号的类型

学习信号可以根据它在训练中表达的判断意义进一步区分。下面先讨论两种常见形式。

### 偏离信号

`偏离信号`是学习信号的一种，指当前状态与训练目标之间出现差距时，被观察到的具体证据。

偏离信号的重点不是笼统地说“输出不好”，而是指出偏离发生在什么信息或行为上。

例如：

```text
训练目标：
压缩上下文时，保留任务边界、失败条件和测试标准。

模型输出：
新版本上下文更短，但删除了失败条件。

偏离信号：
压缩行为达成，但关键约束丢失。
```

这里的偏离信号不是“压缩得不好”，而是指出当前结果中同时出现了目标效果和能力退化。

### 奖励信号

`奖励信号`是学习信号的一种，表示当前状态、输出或行为具有值得保留或强化的价值。

奖励信号可以来自人类偏好、正向标注、版本比较中的“更好”判断，或者测试结果中的稳定改善。

例如：

```text
这一版代码评审先指出了具体风险，比上一版更符合训练目标。
```

这项判断说明当前训练中出现了值得保留的效果，但它仍然不能单独说明具体是哪段上下文导致了这种变化，也不能直接决定下一步如何修改。

## 学习信号是否可靠

一次评估产生了学习信号，不意味着这个信号已经足以支持上下文修改。模型输出具有概率性，评估者可能使用不同标准，运行环境也可能改变行为是否发生。

判断学习信号是否可靠时，需要继续考虑：

- 判断对象和评估依据是否清楚；
- 同类现象是否稳定出现；
- 不同评估方式是否得到相近判断；
- 信号是否混入模型能力、输入信息或运行条件的影响；
- 当前证据是否足以支持保留、回退或继续观察。

因此，学习信号的价值不只取决于它来自真实案例，还取决于它能否在当前训练中形成稳定、可解释、可以继续验证的判断。

## 边界

学习信号不是案例堆积，也不是把人类反馈逐字写入上下文。

评估产生判断，但判断不必然成为可靠的学习信号；学习信号能够为后续训练提供依据，但不直接等同于训练目标、优化方向或上下文修改。
