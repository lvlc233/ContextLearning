# 训练目标

## 从修改上下文开始

在上下文工程中，最经常发生的事情很简单：你改了一段上下文。

看到输出不够具体，就补一条规则；发现某个案例失败，就把案例写进去；觉得回复太长，就删掉一些说明；换了一个 Agent 后表现变差，就再加一段适配要求。

这些修改都可能有用，也都是上下文工程中的常见操作。

但一次修改，很难说明太多东西。

补了一条“回答要更具体”的规则后，下一次输出确实更具体了，但也可能变得更啰嗦。

删掉一段长说明后，回复确实更短了，但也可能丢掉了原本必要的约束。

加入一个失败案例后，那个案例确实不再失败了，但也可能让上下文过度贴合这个案例。

换了一个 Agent 后补了一段适配要求，表现确实暂时恢复了，但也可能让这份上下文更难迁移到其他环境。

如果每次修改只是在回应眼前的问题，上下文很容易变成一组局部补丁：这次补了具体性，下次又破坏简洁性；这次增加工具调用，下次又带来无关检查；这次修复一个 Agent，换到另一个环境又失效。

因此，更关键的问题不是继续问“还要怎么改”，而是先问：这些修改背后，到底想让上下文变成什么样？

是想要它变成一份让 Agent 更少啰嗦的上下文，还是一份让 Agent 更会解释的上下文？它是更贴合当前 Agent，还是更容易迁移到其他环境？它是在补住某个失败案例，还是在形成更一般的判断能力？

当这种追问出现后，问题就不再只是一次上下文修改，而是正式进入了上下文训练领域。

## 什么是训练目标

在上下文学习中，`训练目标` 指的是通过上下文训练希望 Agent 系统能够达到的预期效果或目标状态。它可以是让 Agent 产生某种行为，也可以是保持已有能力不变、减少上下文长度、降低噪声、适配新环境，或在多个约束之间取得更稳定的平衡。

训练目标对于整个上下文训练来说非常重要，没有训练目标，虽然仍然可以有“修改”“尝试”“观察”“比较”的动作，但很难称为训练。因为训练至少意味着：存在某个希望逼近的效果，并且后续变化可以围绕这个效果被判断。

同样是Agent的输出变短，如果训练目标是减少啰嗦，它可能是在接近目标；如果训练目标是详细分析，那它可能是在偏离目标。

训练目标的作用，不是直接判断每一段信息的价值，而是规定当前训练希望追求的状态、行为或效果。后续的评估、学习信号和优化方向，都需要围绕这个目标展开。

如果缺少训练目标，在进行评估时就缺少一个参照对象。面对几乎无穷的语义解释空间，我们可以描述输出发生了什么变化，却难以判断这些变化是否符合本轮训练的追求。这样一来，后续的上下文调整就容易失去统一方向性，逐渐变成对各种现象的分别响应，而不再围绕某个明确目标推进。

## 目标性、训练目标与目标描述

训练过程中的目标，往往不是一开始就以一句完整的目标描述出现。

在实际训练中，某些结果会被持续保留，某些结果会被持续压制，某些效果会被反复逼近。即使训练者还不能准确说出“这次训练到底要达到什么”，这些持续存在的取舍也已经表现出一种方向性。

这种方向性可以称为`目标性`。

训练最先出现的可能不是一句清楚的目标，而是一些偏好、失败现象、版本差异或反馈信号：

```text
这版更短，但没有以前会教。
这个输出看起来稳定，但太早给了答案。
这次评审说了风险，但没有指出风险在哪里。
这个 skill 在原来的 Agent 中能用，换到另一个 Agent 后失效。
```

这些内容本身还不是完整的训练目标，但它们暴露了训练过程中正在被保留、压制或逼近的效果。

随着这些效果被进一步整理，目标性才会被明确为训练目标；写在文档里的目标语句，则是对训练目标的进一步描述。某一次理想输出也只能作为参考样本，而不能直接等同于训练目标。

这里可以区分三层：

| 层次 | 含义 | 例子 |
| --- | --- | --- |
| 目标性 | 训练过程表现出的方向性。 | 具体风险判断被持续保留，泛泛评价被持续压制。 |
| 训练目标 | 目标性所指向的效果或状态。 | Agent 在代码评审中稳定形成可定位、可验证的风险判断。 |
| 目标描述 | 人对训练目标的语言表达。 | 让代码评审更好。 |

这个区分很重要。

如果把目标描述当成训练目标，训练就容易被一句粗糙表达带偏。例如：

```text
让 Agent 代码评审更好。
```

这句话可能实际指向很多不同效果：

```text
更早定位相关文件。
更具体地指出风险。
减少泛泛评价。
补充可验证的测试建议。
降低误报严重性。
保持输出简洁。
```

这些效果之间不一定总是同向。一版输出更短，可能更简洁，也可能丢掉必要推导；一版输出更详细，可能更具体，也可能更啰嗦。

所以，目标描述只是表达方式，不等于训练目标本身。

## 训练目标需要适用范围

训练目标不是脱离环境的全局愿望。

上一章已经说明，同一份上下文换到不同模型、工具权限、运行引擎或输入信息中，可能表现完全不同。因此，一个训练目标通常需要说明它在哪些条件下成立。

至少需要考虑四个范围：

| 范围 | 需要说明的问题 | 例子 |
| --- | --- | --- |
| 受训练对象 | 训练哪段上下文？ | 一份 code review skill，而不是整个 Agent 系统。 |
| 运行环境 | 在哪个模型、工具权限、harness 或运行机制下训练？ | 具备仓库读取权限的 Codex CLI 环境。 |
| 输入范围 | 面向哪些输入、样本或运行记录？ | 后端代码评审样本，而不是所有软件工程场景。 |
| 验证范围 | 在哪些样本、版本或环境中判断有效？ | 当前训练集、未见测试样本、迁移后的 Agent 环境。 |

例如，下面这句目标描述比较粗：

```text
让 code review skill 先指出具体风险。
```

更完整的训练目标可以写成：

```text
在具备仓库读取权限的 Codex CLI 环境中，
面向后端代码评审样本，
训练当前 code review skill，
使 Agent 更稳定地先定位相关文件并指出可验证风险。
```

这样写不是为了啰嗦，而是为了防止训练目标被误解成对所有模型、所有 Agent、所有环境都成立的全局要求。

如果不说明适用范围，训练时很容易把环境问题误判为上下文问题。例如，Agent 没有读取文件，可能不是 skill 没写清楚，而是当前环境没有文件读取权限。

## 训练目标如何进入训练过程

如果训练目标是“评审更具体”，那么指出文件和风险是正向变化；
如果训练目标是“减少干扰性评论”，那么过度展开可能反而是负向变化；
如果训练目标是“提升执行效率”，那么长篇解释可能不是收益，而是成本。

所以训练目标规定的不是“系统会不会变化”，而是训练过程要围绕什么目标进行评估和取舍：

哪些变化需要被保留或回退
哪些观察结果需要被纳入评估
哪些学习信号应当服务于当前目标
哪些现象可以暂时排除在本轮训练之外
哪些修改是在推进当前目标
哪些修改只是对局部现象的响应


训练目标本身不能直接完成训练。

它需要继续转化为训练过程中可以使用的结构：

```text
训练材料；
评估依据；
学习信号解释；
优化方向；
上下文修改方式；
测试标准；
checkpoint 比较方式。
```

例如，目标描述是：

```text
让代码评审更具体。
```

它不能直接驱动训练。训练时需要继续展开：

```text
训练目标：
让 Agent 在代码评审中稳定形成可定位、可验证的风险判断。

训练材料：
包含真实风险、低风险、无风险和权限不足场景的评审样本。

评估依据：
是否指出具体文件、代码位置、风险原因和验证方式。

学习信号：
某次输出只说“整体不错”，说明它没有形成可定位风险判断。

优化方向：
保留已有定位能力，补强风险判断标准，减少泛泛评价。

上下文修改：
调整 code review skill 中关于评审顺序、风险判断和输出边界的规则。
```

这说明，训练目标不是训练时的最终形态。它更像训练过程的效果层约束：训练过程围绕它展开，但真正执行训练时，需要把它落到可观察、可评估、可修改、可验证的结构中。

## 目标诱发上下文

这里还可以引入一个辅助概念：`目标诱发上下文`。

`目标诱发上下文` 指的是：假设存在一份理想的上下文信息，在指定 Agent 系统中加载或使用它后，能够稳定诱发训练目标对应的效果。

它不是某一次输出，也不是已经写好的上下文，而是上下文训练试图逼近的理想上下文状态。

```text
训练目标：
让 Agent 在代码评审时优先指出具体风险。

目标诱发上下文：
一份理想的 code review skill。Agent 加载它后，在具备文件读取权限和合适输入信息时，能稳定先定位相关代码，再形成可验证风险判断。
```

这个概念的作用是区分两个层次：

```text
训练目标位于预期效果层。
目标诱发上下文位于上下文本体层。
```

训练不是直接修改目标，而是通过修改当前上下文，逐步逼近那份能够诱发目标效果的理想上下文状态。

最后，需要把训练目标和几个相邻概念区分开。

训练目标不是某次理想输出。某次输出可以作为样本或参考，但不能直接等同于训练目标。

训练目标也不是上下文规则。规则是可能被写入上下文的内容，目标是这些规则希望服务的预期效果。

训练目标不是学习信号。学习信号来自运行、评估、标注或版本对比，是关于当前状态是否有学习价值的信息。

训练目标也不是优化方向。优化方向是在某个目标下，根据学习信号整理出的下一步调整方向。

可以暂时把关系理解为：

```text
训练目标：希望逼近、保持、强化或避免什么效果。
训练材料：用什么材料暴露或承载这个目标。
评估依据：如何判断是否接近这个效果。
学习信号：一次运行、评估或标注提供了什么有学习价值的信息。
优化方向：下一步应该往哪里调整。
上下文修改：实际改什么。
```

明确训练目标之后，下一步就需要准备训练材料。

也就是：

```text
哪些样本能暴露这个目标？
哪些运行记录能说明目标达成或偏离？
哪些标注可以帮助形成学习信号？
哪些测试材料可以验证训练是否真的有效？
```

## 如何找到训练目标

很多失败的 `上下文训练`，问题通常不是规则太少，而是目标没有被看清。

例如：

```text
上下文让 Agent 的回复质量更好。
```

这不是一个好的训练目标，因为它太抽象，难以判断输出是否变好，也很难指导上下文应该如何修改。

更好的做法是先写出偏差，再提炼训练目标。

偏差描述：

```text
加载这份上下文后，Agent 经常泛泛而谈，没有回应当前任务的具体条件。
当任务已有明确输出标准时，Agent 只给出笼统评价，没有指出输入与标准之间的具体偏差。
当上下文规则之间发生冲突时，Agent 会优先执行局部规则，而不是当前任务目标。
```

对应的训练目标：

```text
加载这份上下文后，Agent 应减少泛泛而谈的回复，优先给出和当前任务相关的具体判断。
当任务已有明确输出标准时，Agent 应指出输入与标准之间的具体偏差。
当上下文规则之间发生冲突时，Agent 应优先遵循当前任务目标。
```

这些目标能落到行为上，也更容易测试。具体场景中的经验可以作为训练样本或证据，但不应直接等同于上下文学习领域的通用概念。

## 独立性

在指定训练目标时，应尽量确保 `训练目标` 具有一定的独立性。

例如：

- 反馈质量；
- 引导方向；
- 输出信息密度；
- 规则冲突处理；
- ...

基于独立性优先的训练目标有以下好处：

- 避免多个目标互相干扰；
- 方便观察评估；
- ...

某些目标实际上可能隐含多个子目标。如果直接执行训练，一轮训练中就会很难判断到底是哪部分修改起了作用。

例如：

- “我想要这段上下文可以让模型生成的前端更加好看。”

这个目标可能同时包含视觉风格、布局密度、组件选择、信息层级、响应式表现等多个方向。更好的做法是先拆出当前最需要训练的主要目标。

## 目标关系

训练目标不是简单的平铺列表。多个训练目标之间可能存在独立、组合或条件关系。

`独立目标` 指偏离信号可以相对单独观察和判断的目标。它适合用于训练早期，因为信号更清晰，更容易判断某次上下文修改是否真的改善了对应行为。

`组合目标` 指真实任务中需要同时成立的一组目标。组合目标更接近实际使用场景，但训练信号也更混杂，容易出现某个目标改善、另一个目标退化的情况。
