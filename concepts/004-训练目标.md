# 训练目标

从本章开始,我们将正式进入CL的学习...

上下文学习中,我们训练什么?

想象一下....

## 从行为归因到训练判断

Agent 行为不是上下文单独决定的结果，而是上下文信息、模型能力、运行环境、输入信息和运行引擎共同作用后的表现。

这意味着，在上下文训练中，观察到一次输出变化还不够。一次输出变好，可能来自上下文修改，也可能来自模型能力、工具权限、任务输入、采样结果或运行引擎的变化；一次输出失败，也不一定说明上下文写错了。

因此，在讨论“怎么改上下文”之前，需要先回答一个更基础的问题：

```text
这次训练希望逼近什么效果？
```

这个问题就是 `训练目标` 所在的位置。

系统归因让我们知道一次行为结果可能由哪些因素共同造成；训练目标则让我们知道，在这些因素中，哪些变化对当前训练有意义，哪些只是背景条件、偶发现象或副作用。

如果没有训练目标，系统归因只能停留在分析层：我们可以列出很多可能原因，却无法判断哪些原因应该被纳入训练，哪些原因应该被排除，哪些效果应该保留，哪些效果应该回退。

所以，训练目标不是一个可有可无的字段。它是把 Agent 行为观察转化为可评估、可迭代训练过程的判断锚点。

## 什么是训练目标

`训练目标` 指上下文训练希望达到的预期效果或目标状态。

在上下文训练中，训练目标不是某一句写出来的目标语句，也不是某一次理想输出，而是训练过程试图逼近的效果。

这个效果可以是行为层面的。例如：

```text
让 Agent 在代码评审时先定位具体文件，再指出可验证的风险。
```

它也可以是上下文状态层面的。例如：

```text
减少上下文长度，同时不破坏已有能力。
```

也可以是环境适配层面的。例如：

```text
让一份已经在某个 Agent 中有效的 skill，迁移到另一个 Agent 后仍然可用。
```

还可以是多目标平衡。例如：

```text
在保持评审具体性的同时，减少不必要的长篇解释。
```

因此，训练目标不应该被窄化为“希望 Agent 产生某种行为”。行为目标很常见，但训练目标还可以指向能力保持、上下文压缩、噪声降低、环境适配、稳定性提升，或多个约束之间的平衡。

## 目标与目标描述

`目标描述` 是人用语言写出来表达训练目标的方式。它可能准确，也可能含混。

例如：

```text
让 Agent 代码评审更好。
```

这是一句目标描述，但它并没有清楚说明训练到底要逼近什么。它可能实际指向很多不同目标：

```text
更早定位相关文件。
更具体地指出风险。
减少泛泛评价。
补充可验证的测试建议。
降低误报严重性。
保持输出简洁。
```

如果不拆开，训练时就很难判断一次修改到底改善了什么。

比如，一次修改让输出更短，可能改善了“保持简洁”，但也可能破坏了“补充测试建议”。一次修改让输出更详细，可能改善了“风险解释”，但也可能破坏了“减少冗余”。

因此，需要区分：

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| 训练目标 | 训练希望逼近的预期效果或目标状态。 | 代码评审时稳定指出可定位、可验证的风险。 |
| 目标描述 | 对训练目标的语言表达。 | 让代码评审更好。 |

很多训练失败不是因为完全没有目标，而是因为目标描述太粗，导致实际目标没有被看清。

## 训练目标的适用范围

训练目标不是脱离环境的全局愿望。

上一章已经说明，同一份上下文换到不同模型、工具权限、运行引擎或任务输入中，可能表现完全不同。因此，一个训练目标通常需要说明它在哪些条件下成立。

至少需要考虑四个范围：

| 范围 | 需要说明的问题 | 例子 |
| --- | --- | --- |
| 受训练对象 | 训练哪段上下文？ | 一份 code review skill，而不是整个 Agent 系统。 |
| 运行环境 | 在哪个模型、工具权限、harness 或运行机制下训练？ | 具备仓库读取权限的 Codex CLI 环境。 |
| 任务范围 | 面向哪些任务或样本？ | 后端代码评审任务，而不是所有软件工程任务。 |
| 验证范围 | 在哪些样本、版本或环境中判断有效？ | 当前训练集、未见测试样本、迁移后的 Agent 环境。 |

例如，下面这句目标描述比较粗：

```text
让 code review skill 先指出具体风险。
```

更完整的训练目标可以写成：

```text
在具备仓库读取权限的 Codex CLI 环境中，
面向后端代码评审任务，
训练当前 code review skill，
使 Agent 更稳定地先定位相关文件并指出可验证风险。
```

这样写并不是为了啰嗦，而是为了防止训练目标被误解成对所有模型、所有 Agent、所有环境都成立的全局要求。

如果不说明适用范围，训练时很容易把环境问题误判为上下文问题。例如，Agent 没有读取文件，可能不是 skill 没写清楚，而是当前环境没有文件读取权限。

所以，训练目标的适用范围本身也是训练判断的一部分。

## 目标与训练结构

训练目标是一层抽象锚点，但它不是训练过程中直接使用的全部结构。

实际训练时，目标通常需要继续转化为：

```text
训练材料；
评估依据；
学习信号解释；
优化方向；
上下文修改方式；
测试标准；
checkpoint 比较方式。
```

例如，目标描述是：

```text
让代码评审更具体。
```

它不能直接驱动训练。训练时需要继续展开：

```text
评估依据：
是否指出具体文件、代码位置、风险原因和验证方式。

训练材料：
包含真实风险、低风险、无风险和权限不足场景的评审样本。

学习信号：
某次输出只说“整体不错”，说明它没有形成可定位风险判断。

优化方向：
保留已有定位能力，补强风险判断标准，减少泛泛评价。

上下文修改：
调整 code review skill 中关于评审顺序、风险判断和输出边界的规则。
```

这说明，训练目标不是训练时的最终形态。它更像训练结构的上层约束：训练过程要围绕它展开，但真正执行训练时，需要把它落到可观察、可评估、可修改、可验证的结构中。

这里也可以引入一个辅助概念：`目标诱发上下文`。

`目标诱发上下文` 指的是：假设存在一份理想的上下文信息，在指定 Agent 系统中加载或使用它后，能够稳定诱发训练目标对应的效果。

它不是某一次输出，也不是已经写好的上下文，而是上下文训练试图逼近的理想上下文状态。

```text
训练目标：
让 Agent 在代码评审时优先指出具体风险。

目标诱发上下文：
一份理想的 code review skill。Agent 加载它后，在具备文件读取权限和合适任务输入时，能稳定先定位相关代码，再形成可验证风险判断。
```

这个概念的作用是区分两个层次：

```text
训练目标位于预期效果层。
目标诱发上下文位于上下文本体层。
```

训练不是直接修改目标，而是通过修改当前上下文，逐步逼近那份能够诱发目标效果的理想上下文状态。

## 从现象中提炼目标

训练目标不一定一开始就清楚。

很多时候，人类先看到的是一些偏好、失败现象或版本差异：

```text
这版更短，但没有以前会教。
这个输出看起来稳定，但太早给了答案。
这次评审说了风险，但没有指出风险在哪里。
这个 skill 在原来的 Agent 中能用，换到另一个 Agent 后失效。
```

这些内容本身还不是训练目标。它们更像目标尚未被准确表达之前留下的材料。

从这些材料中，可以逐步提炼训练目标：

| 原始现象 | 可能提炼出的训练目标 |
| --- | --- |
| 输出很短，但用户觉得“不如以前会教”。 | 在保持简洁的同时保留必要推导过程。 |
| Agent 经常泛泛评价代码。 | 评审时优先形成可定位风险判断。 |
| 换 Agent 后 skill 失效。 | 适配新运行环境，保持核心行为不退化。 |
| 上下文越改越长。 | 降低上下文冗余，同时保持关键能力。 |

因此，训练目标可以在训练开始前被明确写出，也可以在训练过程中通过材料、标注、失败案例和版本对比逐步被显式化。

这里不需要把目标分成“显式目标”和“隐式目标”两类对象。更准确的说法是：

```text
训练目标本身是训练希望逼近的预期效果；
显式或隐式描述的是这个目标是否已经被清楚表达出来。
```

## 边界与下一步

最后，需要把训练目标和几个相邻概念区分开。

训练目标不是某次理想输出。某次输出可以作为样本或参考，但不能直接等同于训练目标。

训练目标也不是上下文规则。规则是可能被写入上下文的内容，目标是这些规则希望服务的预期效果。

训练目标不是学习信号。学习信号来自运行、评估、标注或版本对比，是关于当前状态是否有学习价值的信息。

训练目标也不是优化方向。优化方向是在某个目标下，根据学习信号整理出的下一步调整方向。

可以暂时把关系理解为：

```text
训练目标：希望达到什么效果。
评估依据：如何判断是否接近这个效果。
学习信号：一次运行、评估或标注提供了什么有学习价值的信息。
优化方向：下一步应该往哪里调整。
上下文修改：实际改什么。
```

明确训练目标之后，下一步就需要准备训练材料。

也就是：

```text
哪些样本能暴露这个目标？
哪些运行记录能说明目标达成或偏离？
哪些标注可以帮助形成学习信号？
哪些测试材料可以验证训练是否真的有效？
```

## 本章引出的概念

- 训练目标

`训练目标` 指上下文训练希望达到的预期效果或目标状态。

训练目标可以是让 Agent 产生某种行为，也可以是保持已有能力不变、减少上下文长度、降低噪声、适配新环境，或在多个约束之间取得更稳定的平衡。它不一定在训练开始时就完全清楚，也不一定一开始就以明确规则的形式存在。

找到一个能够精确表达实际需求的 `训练目标`，是整个 `上下文学习` 过程中非常重要的一步。如果缺少 `训练目标`，或者对 `训练目标` 的描述不明确，整个系统就很难达到实际想要的效果。

缺少 `训练目标` 的 `上下文学习`，就像在没有靶心的情况下调参：上下文也许一直在被修改，但每一次修改都很难判断是接近目标，还是只是制造了新的偏移。这也是很多 `上下文学习` 失败的原因。

这里的“缺少训练目标”通常不是指完全没有任何意图，而是指训练目标尚未被显式化。它可能仍然隐含在人类偏好、样本表现、失败现象、数据标注或版本对比中。

## 如何找到训练目标

很多失败的 `上下文训练`，问题通常不是规则太少，而是目标没有被看清。

例如：

```text
上下文让 Agent 的回复质量更好。
```

这不是一个好的训练目标，因为它太抽象，难以判断输出是否变好，也很难指导上下文应该如何修改。

更好的做法是先写出偏差，再提炼训练目标。

偏差描述：

```text
加载这份上下文后，Agent 经常泛泛而谈，没有回应当前任务的具体条件。
当任务已有明确输出标准时，Agent 只给出笼统评价，没有指出输入与标准之间的具体偏差。
当上下文规则之间发生冲突时，Agent 会优先执行局部规则，而不是当前任务目标。
```

对应的训练目标：

```text
加载这份上下文后，Agent 应减少泛泛而谈的回复，优先给出和当前任务相关的具体判断。
当任务已有明确输出标准时，Agent 应指出输入与标准之间的具体偏差。
当上下文规则之间发生冲突时，Agent 应优先遵循当前任务目标。
```

这些目标能落到行为上，也更容易测试。具体场景中的经验可以作为训练样本或证据，但不应直接等同于上下文学习领域的通用概念。

## 显式目标与隐式目标

训练目标可以分为显式目标和隐式目标。

`显式目标` 指已经被写成可观察行为的目标。例如：

```text
加载这份上下文后，Agent 应指出输入与标准之间的具体偏差。
```

`隐式目标` 指还没有被明确写出，但已经存在于人类偏好、样本表现、数据标注、失败现象或版本对比中的目标。例如：

```text
这个回复虽然更短，但不如上一版会教。
这版看起来更稳定，但它太早给出了答案。
这个输出不差，但没有回应用户当前卡住的位置。
```

这些反馈或标注本身不是训练目标，但它们可能包含尚未显式化的训练目标。上下文训练的一部分工作，就是从这些训练信号中逐步提炼出更明确的目标。

因此，训练目标不一定总是训练的起点。它也可以是训练过程中被发现、修正和显式化的对象。

## 独立性

在指定训练目标时，应尽量确保 `训练目标` 具有一定的独立性。

例如：

- 反馈质量；
- 引导方向；
- 输出信息密度；
- 规则冲突处理；
- ...

基于独立性优先的训练目标有以下好处：

- 避免多个目标互相干扰；
- 方便观察评估；
- ...

某些目标实际上可能隐含多个子目标。如果直接执行训练，一轮训练中就会很难判断到底是哪部分修改起了作用。

例如：

- “我想要这段上下文可以让模型生成的前端更加好看。”

这个目标可能同时包含视觉风格、布局密度、组件选择、信息层级、响应式表现等多个方向。更好的做法是先拆出当前最需要训练的主要目标。

## 目标关系

训练目标不是简单的平铺列表。多个训练目标之间可能存在独立、组合或条件关系。

`独立目标` 指偏离信号可以相对单独观察和判断的目标。它适合用于训练早期，因为信号更清晰，更容易判断某次上下文修改是否真的改善了对应行为。

`组合目标` 指真实任务中需要同时成立的一组目标。组合目标更接近实际使用场景，但训练信号也更混杂，容易出现某个目标改善、另一个目标退化的情况。
