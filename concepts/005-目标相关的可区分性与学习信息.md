# 目标相关的可区分性与学习信息

## 从训练中的信息开始

前面几章已经说明：上下文训练不是直接观察上下文本身，而是让 Agent 在具体环境中运行，再观察它实际产生了什么行为和结果。

一次运行中，可以记录 Agent 的最终输出、工具调用、执行结果、环境状态、人工评论和运行记录；上下文信息本身及其版本变化，也可以被读取、比较和讨论。本文将这类能够被记录、读取、传递、存储或解释的内容统称为`信息`。

这些信息首先说明的是：运行中发生了什么。

例如，Agent 没有读取某个文件、工具调用失败、测试没有通过，或某个上下文版本使输出变短，都是可以观察到的信息。它们并不会自动说明这次变化应当被保留、抑制，还是仅仅继续观察。

同一项信息在不同训练中也可能具有不同含义。输出变短，在“减少啰嗦”的训练中可能是改善；在“保留完整分析”的训练中则可能意味着能力丢失。问题不在于信息本身缺少内容，而在于它尚未与当前训练建立能够影响后续变化的关系。

训练中还有另一类常用说法：当某段信息被系统或训练者用于后续学习、自优化或调整时，本文将其统称为`学习信息`，也可以称为`学习信号`。

这不是一种严格的对象分类。标签、误差、梯度、环境反馈和评估判断在来源、形式和训练中的作用位置上并不相同；“学习信息”只是用来指代它们进入后续学习过程时所承担的共同角色。人类评估是活动而非信息，评估形成的判断或标注才可能成为学习信息；环境反馈同样需要在被读取、关联或使用后，才以学习信息的形式参与训练。

## 学习信息为什么仍然需要区分

训练过程中出现的信息很多，但训练不能对所有信息作出同等响应。

即使一段信息已经被用于后续学习，也不意味着它单独就足以说明系统应当怎样变化。一次环境反馈可能只描述环境发生了什么；一个 loss 数值需要放在具体任务、模型状态和计算方式中理解；一条人类评论也可能仍然过于模糊，无法支持可靠调整。

学习过程要发生有方向的变化，就需要使当前训练中的不同可能性不再被同等对待。例如，系统需要能够看出：两个候选结果并不一样，其中一个更接近当前目标；某次失败并非普通波动，而是暴露出需要处理的偏离；某个版本的改善值得被保留。

这种结构，本文称为`目标相关的可区分性`。

## 什么是目标相关的可区分性

`目标相关的可区分性`指的是：在当前训练目标下，不同状态、行为、结果或候选方案不再被同等对待，并且这种差异能够进一步影响训练过程。

它不是一种具体的信号，也不是某个固定的计算方法。标签、loss、奖励、偏好判断、测试结果和环境反馈在训练中承担的角色并不相同；它们可以提供、建立、计算、记录或使用与训练目标有关的差异，但不能因此被视为同一种信息。

例如，单独看到“测试失败”时，只知道某个结果没有通过。将它放到“Agent 应完成登录跳转功能”的训练目标下，并确认失败发生在 Agent 选择的调用方式之后，才可以进一步区分：这种行为不能被继续当作与成功行为同等的候选。

目标相关的可区分性也不意味着已经得到了完整的修改方案。它只使训练能够开始区分：什么更接近目标，什么发生了偏离，什么尚不足以判断。

## 学习信息与目标相关的可区分性

学习信息不等于目标相关的可区分性。前者是训练过程中被使用的信息；后者是学习过程能够对不同可能性作出目标相关区别的性质。

两者的关系也不应被写成固定流水线。某些学习信息提供比较的参照，某些学习信息记录当前结果，某些学习信息计算或表达差异，某些学习信息则已经直接服务于更新或调整。它们在不同训练方式中的位置并不相同。

例如：

```text
标签可以参与确定预测与预期之间的差异；
loss 可以表达这种差异的大小；
梯度可以将差异进一步转化为参数更新所使用的信息；
环境反馈可以提供结果，但可能仍需要结合目标和行为解释；
评估判断可以直接说明某项表现相对于当前依据具有何种价值。
```

训练目标、学习信息和优化方向也不是同一个概念。训练目标规定当前训练希望逼近、保持或避免什么效果；学习信息是在过程中被用于学习或调整的内容；优化方向则是这些内容被进一步组织后，对下一步调整形成的指引。

因此，环境反馈尤其需要区分。任务成功、工具失败、用户接受或拒绝、环境状态变化，都可以提供学习过程可能使用的信息；但它们本身不必然已经说明这项反馈与当前目标有什么关系，也不必然足以支持后续调整。

## 可区分性如何出现

目标相关的可区分性没有唯一来源，也不要求每段信息经过相同的步骤。下面列出的情况只是训练中常见的形成方式。

### 评估

人、Agent、规则或其他评估系统，可以根据某种判断依据，对对象形成价值判断。这个判断能够使对象相对于当前依据表现为可取、不可取、重要、存疑或需要继续观察，从而形成目标相关的差异。

### 差异、误差与测试结果

预期状态与实际结果之间的差异，可以暴露当前状态没有与某种要求一致。预测误差、约束未满足、测试失败或指标变化都属于这类情况；但差异本身只说明“不一致”，仍需要结合当前训练确认它是否构成需要处理的偏离。

### 比较与偏好

将两个输出、上下文版本或运行结果放在一起时，可以形成排序、选择或偏好。比较不说明某个对象在所有条件下都更好；它说明的是，在当前比较条件下，两个对象不应再被同等对待。

### 环境反馈与运行结果

环境可以返回任务成功或失败、工具执行状态、用户反应、奖励或状态变化。这些结果有时已足以支持后续处理，有时仍只是需要解释的事实。训练过程需要确认：反馈与什么行为、什么条件和什么目标有关。

### 聚合与模式提取

单次运行可能具有偶然性。将多次运行、多个样本或不同版本中的信息放在一起，可以发现稳定偏差、重复效果或特定条件下才会出现的变化。聚合不直接给出修改方案，但可能使原本孤立的现象成为更可靠的训练信息。

这些方式可以组合发生。一项测试结果可以作为评估依据；一次比较可以形成偏好后再接受评估；环境反馈也可以与运行记录共同参与对 Agent 行为的判断。

## 评估：形成可区分性的一种方式

`评估`是从某种判断依据出发，对事物形成价值判断的过程。

这里说评估形成价值判断，并不需要进一步声称价值是由评估创造的，还是在评估之前已经存在。对上下文训练而言，更重要的是：评估使某个对象与判断依据发生关系，并形成关于它是否可取、是否重要或具有什么价值的判断信息。

评估不要求判断依据必须被清晰写成规则。它可以来自训练目标、需求、偏好、经验、指标或其他尚未完整语言化的感受和倾向。判断依据是否明确，会影响评估能否被解释、复现和验证，但不决定评估是否能够发生。

### 评估对象与相关信息

评估不限定于某一种对象。信息、行为、结果、方案、状态、轨迹，以及它们之间的变化，都可以成为被评估的事物。

评估时使用的信息不一定就是评估对象本身。一份运行记录可以直接接受评估，也可以作为判断某项行为或结果的相关信息；一项测试结果可以接受评估，也可以帮助判断某个上下文版本是否产生了预期效果。

因此，在一次评估中需要区分：什么正在接受评估，哪些信息被用于形成判断，以及判断依据来自哪里。三者可以重合，但不是同一个概念。

### 评估案例

你完成了一个登录跳转功能，并让加载了 code review skill 的 Agent 评审这次修改。运行结束后，Agent 给出报告：

```text
1. src/auth/redirect.ts:42
   redirectUrl 来自请求参数，缺少允许域名限制，
   可能产生开放重定向风险。

2. src/auth/session.ts:18
   用户 ID 被写入 session，可能泄露用户隐私。

3. 测试建议
   建议补充正常登录和登录失败场景的测试。
```

这份报告本身来自一次评估：Agent 根据 skill 中的要求判断代码风险。你阅读报告时，又开始评估这份报告是否可靠。继续检查代码、配置和运行记录后，可以发现：开放重定向风险定位正确；session 中的用户 ID 并不构成该报告所说的隐私风险；测试建议没有验证开放重定向场景；Agent 还遗漏了决定风险是否成立的白名单配置文件。

从 Agent 评估代码，到你评估报告，再到结合更多信息重新判断 Agent 的评审行为，评估在这里围绕不同对象发生了多次。对象、相关信息和判断依据不同，但每次评估都在形成某种不应被同等对待的差异。

### 价值判断具有相对性

评估形成的价值判断总是相对于某种依据出现。同一个对象，在不同目标、条件或参照下可能得到不同评价；同一种表现，也可能同时具有正面价值、负面价值或尚待确认的价值。

这并不意味着评估只能是任意的主观偏见。规则、测试和可观察结果也可以提供判断尺度。评估的相对性说明的是判断总有其成立条件，而不是所有判断都同样可靠。

### 评估与其他活动的边界

观察、测量、验证和分析都可能参与评估，但它们并不天然等于评估。

```text
观察：发现发生了什么。
测量：获得某项状态或数值。
验证：确认某项陈述是否成立。
分析：理解结构、关系或原因。
评估：从判断依据出发，形成关于对象价值的判断。
```

这些活动可以组合发生。例如，训练者可以先观察 Agent 行为，再通过测试验证结果，分析问题出现的条件，最后形成关于当前表现是否可接受的评估判断。

评估本身不直接负责解释问题为什么发生，也不直接决定接下来应当怎样修改或行动。价值判断可以继续支持归因、决策和优化，但这些属于评估之后可能发生的活动。

## 学习信息在上下文训练中的位置

在上下文训练中，学习信息可以包括评估判断、差异与误差、环境反馈、测试结果、偏好比较、数据标注或多次运行中提取出的稳定模式。它们的来源和形式不同，也不都处于同一个训练环节。

假设当前训练目标是让 Agent 形成可定位、可验证的风险判断。前述案例中，准确定位开放重定向风险、将正常 session 行为误报为隐私风险、遗漏关键配置文件，以及测试建议未覆盖相应风险，都可以作为后续训练使用的学习信息。它们分别说明当前行为中哪些效果值得保留，哪些偏离需要处理，哪些现象还需要进一步确认。

这些学习信息仍然不能单独说明问题为什么发生，也不能直接给出如何修改 skill。它们需要结合受训练对象、运行条件和其他相关信息，进一步支持优化方向和上下文修改。

## 边界

学习信息不是案例堆积，也不是把人类反馈逐字写入上下文。

目标相关的可区分性不是一种新的固定评分函数，更不是要求所有训练都使用同一种评估形式。它说明的是：训练要发生有方向的变化，就需要让不同可能性在当前目标下不再被同等对待。

评估是形成这种差异的重要方式，但不是唯一方式；评估判断、测试结果或环境反馈也不必然自动足以支持后续调整。学习信息能够参与后续训练，但不直接等同于训练目标、优化方向或上下文修改。
