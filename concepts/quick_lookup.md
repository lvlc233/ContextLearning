## 训练概念

| 名字 | 解释 | 案例 | 出自 |
|---|---|---|---|
| 上下文训练 | `上下文训练` 是 `上下文学习` 中的具体实践过程，是指通过某种具体的训练方式，获得或调整一段 `上下文信息`，使 Agent 系统在目标环境中使用这段上下文信息时，可以更稳定地达到训练目标的过程。 | - | null |
| 训练目标/目标 | `训练目标` 指训练希望达到的预期效果或目标状态。它可以是让 Agent 产生某种行为，也可以是保持已有能力不变、减少上下文长度、降低噪声、适配新环境，或在多个约束之间取得更稳定的平衡。请注意，对 `期望` 的描述不等同于 `期望` 本身，例如“让模型更加聪明”可能实际表达的是“不啰嗦”、“指令遵循”、“具有自主性”等更具体的期望。 | 目标：“让模型变得更加聪明”的期望；目标描述：“让模型变得更加聪明”。 | null |
| 目标诱发上下文/目标上下文 | 源于机器学习领域中 `目标函数`的概念，`目标上下文`指的是：假设存在一份理想的`上下文信息`，在指定的`上下文环境`中，能使模型加载完这段`上下文信息`后能够稳定的达到某个`目标`。它不是已经写好的上下文，而是上下文训练试图逼近的理想上下文状态。| 目标是“代码评审时先指出具体风险”；目标诱发上下文是一份被加载后能稳定诱发该评审行为的理想上下文信息，而不是某一次评审输出 |null|
| 优化方向 | 参考自`机器学习`领域中 `梯度`的概念，`梯度`被描述为 "当模型发生参数调整后,每个参数往哪个方向变，会让损失增加得最快。",而`优化方向`更加一般化，它是指"基于当前训练目标的信息状态，系统通过所得到的反馈信号而获得的具有指导方向意义的信息"，而在`上下文学习`中，这一个过程通常指的就是 当前的上下文信息在注入到运行环境后，通过收集分析实际输出并给出具有指导方向含义的信息。 | 目标是“让 agent 的代码评审更具体”。当前上下文注入后，agent 只说“整体不错”，没有指出具体风险；这个输出形成负向反馈信号。分析后得到的优化方向不是直接补一条新规则，而是确认下一轮修改应朝“减少泛泛评价、增加可定位风险判断”的方向逼近。 | null|
| 信息 | 能够被记录、读取、传递、存储或解释的内容。一句话、一张图片、一个数字、一段模型输出都可以是信息。 | “今天下雨”“温度是 28°C”“模型输出了一段评审意见”都属于信息。 | null |
| 信号 | 能够被观察到，并被赋予某种指示意义的现象或信息，常见于某些判定、传递或触发场景。红绿灯、0/1 电平、体温都可以是信号。 | 红灯是“停止”的信号；手机提示音是“有新消息”的信号；0/1 电平可以承载数字信息。 | null |
| 学习信号 | 源于 `机器学习`领域中的 signal，即学习系统在训练过程中可获得的反馈、监督或评价信息，它可以来自某个评估函数、环境反馈或人类标注...重点在于它用于判断当前状态与目标之间的关系，并为后续调整提供依据。而在`上下文学习`中，这种信息更多表现为自然语言形式的反馈、标注或测试结果等。| 模型输出“整体不错”但没有指出具体风险，人工标注“负向，因为缺少可定位风险”，这条标注就是学习信号；评估规则规定：如果代码评审没有指出具体风险，则记为负向；如果指出可定位风险，则记为正向。某次输出只说“整体不
  错”，因此该规则产生了“负向学习信号” | null |
| 偏离信号 | 一种描述当前状态与训练目标之间差距的学习信号。它指出模型输出、上下文修改或测试结果相对于目标的具体偏差证据。 | 输出更短，但删除了失败条件。 | null |
| 奖励信号 | 一种表示当前状态、输出或行为值得被强化的学习信号。可以表现为人类偏好、正向标注、版本比较中的“更好”判断。 | “这一版先指出具体风险，比上一版更符合目标。” | null |
| 评估 | `评估` 指的是根据某种标准，对当前信息进行价值判断的过程。在`上下文学习`中，包括人类数据标注、一份规则进行自动判断...都可以属于`评估`，一般来说，我们通过某种`评估`方式将一般信息转化为可用于`训练`的`信号`。 | 模型输出“整体不错，可以合并”；评估其是否指出具体风险后，得到“未指出具体风险”的负向学习信号。 | null |

## 工程概念
| 名字 | 解释 | 案例 | 出自 |
|---|---|---|---|
| 数据集 | 按照一定规律组织起来的数据的集合，在`上下文学习`中，由于面向的主体是上下文并基于Agent进行训练，因此数据组织的方式与格式更加的灵活 | 常见数据组织方式：Q 表示任务输入或原始运行片段，A 表示模型输出，T 表示人类标注。 | null |
| 训练数据集 | 用于实际训练过程的数据集，通常以输入项为主。 | 例如一条训练样本是：Q=请评审这段登录接口代码是否有安全风险；输入代码包含未校验的 redirect_url。 | null |
| 测试数据集 | 用于验证训练后的上下文是否改善输出、是否具有泛化能力的数据集。 | 例如一条训练样本是：Q=请评审这段登录接口代码是否有安全风险；输入代码包含未校验的 redirect_url。 | null |
| 训练方案 | 一次训练开始前，对训练目标、样本范围、轮次、采样次数、记录方式、评估方式、修改范围、checkpoint 等内容的执行安排。它不仅描述训练要怎么执行，也包含用于控制训练过程的关键控制项。 | - | null |
| 过拟合 | 指上下文在`训练`后过度适配局部训练材料、偏好或场景特征，导致在装载上下文后的Agent在未见任务、不同上下文环境或更一般目标下表现变差或无法达成目标。 | 规则只适配某一次代码评审案例，换一类代码后反而无法指出真实风险。 | null |
| 欠拟合 | 指上下文在`训练`后仍未充分达成训练目标，导致Agent即使在训练样本上也难以稳定产生目标行为。 | 已训练“代码评审要指出具体风险”，但模型在训练样本上仍经常只给出“整体不错”的泛泛评价。 | null |
| 浅学习 | `浅学习` 并不是特指某种过拟合或欠拟合的结果，而是表示一种`上下文学习`现象，即训练得到的`上下文`只是学到案例或规则的表层形状，而不是更加本质内容特征。在使用案例时，这种情况会十分容易发生，训练时需要重点观察 | - | null |
| 后训练 | 指在已有训练结果的基础上继续进行的训练活动。它不从零开始，而是在保留已有核心能力或结构的前提下，对上下文进行进一步适配、校准或增强。 | 一份代码评审上下文已经能稳定指出风险；后训练继续适配不同 Agent、工具环境或表达偏好，而不是重新训练整份上下文。 | null |
| checkpoint | 指训练过程中保存下来的阶段性上下文状态。方便后续比较、回退或继续训练。 | 813s-20250615-verify-control.md：“上下文状态...” | null |
